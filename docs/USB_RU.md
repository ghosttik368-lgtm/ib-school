# Флешка: образы, модели и отдельные аккаунты

## Подготовка исходного компьютера

1. Обновите исходники и запустите `py tools/ib.py start --build`.
2. Выполните `py tools/ib.py check`. Дождитесь успешных проверок сайта и включённого C++. По умолчанию AI выключен: модели не нужны. Для переноса с AI добавьте --with-ai к первому запуску.
3. Во время экспорта не обновляйте модели и исходники. Экспорт содержит установочный комплект без пользователей, курсов и материалов.
4. Выполните `py tools/ib.py export-usb "D:\IB_USB"`. Папка должна быть новой. Служебный Python-образ при необходимости будет скачан один раз.
5. Дождитесь строки «Готово». При ошибке незавершённая папка не является рабочим комплектом.

Скопируйте всю папку на флешку с поддержкой файлов больше 4 ГБ (например, exFAT/NTFS). Размер определяется фактическими образами и моделями. Не переименовывайте и не редактируйте содержимое комплектов: при импорте проверяются SHA-256.

Состав комплекта:

| Файл/папка | Содержимое |
|---|---|
| `project/` | Проверенные исходники, Compose, короткая инструкция |
| `images.tar` | Веб-приложение, PostgreSQL, Caddy и включённые обработчики; при AI=off образов AI нет |
| `ollama_models.tar.gz` | Только при AI=on: веса Qwen; без ключей Ollama |
| `whisper_models.tar.gz` | Только при AI=on: выбранная Whisper; без временных кэшей |
| `usb-manifest.json` | Архитектура, выбранные модели, теги и контрольные суммы |

Настройки `.env.deploy`, секреты, база и материалы в этот установочный комплект не попадают. На новой машине генерируются новые ключи. Существующая учебная база переносится штатной резервной копией, а выданные аккаунты — отдельным приватным архивом.

## Новая машина

Docker, WSL 2 и Python должны быть установлены заранее. Запустите Docker Desktop. На Linux используйте Docker Engine с Compose v2 и команды `python3` вместо `py`.

1. Скопируйте `IB_USB` на локальный диск. Архитектура Docker должна совпадать с исходной машиной.
2. Откройте терминал в `IB_USB/project`.
3. Выполните:

```powershell
py tools/ib.py import-usb ".."
```

Команда проверит целостность, загрузит образы, восстановит модели в тома и запустит Compose без скачивания и пересборки. На этой машине не должно быть существующих томов проекта `ib-school-local`, а в папке проекта — `.env.deploy`. Проверка предотвращает перезапись работающей установки. При незавершённом импорте сохраните сообщение об ошибке; не удаляйте тома наугад.

4. Распакуйте отдельно `IB_ACCOUNTS_1000_PRIVATE.zip` и выполните:

```powershell
py tools/ib.py import-accounts "D:\IB_ACCOUNTS_1000_PRIVATE\accounts.json"
```

5. Откройте http://localhost:8080. Логин первоначального администратора — `admin001`, пароль — из приватной таблицы.

Следующие запуски (для варианта с AI добавьте --with-ai; без этого флага нейросети выключаются):

```powershell
py tools/ib.py start --offline
```

Если нужна именно существующая учебная база с курсами и результатами, используйте `tools/backup_compose.py` и `tools/restore_backup.py` по серверной инструкции. Набор из 1000 аккаунтов — стартовая пустая учебная база, он не содержит ваших прежних курсов.

## Что хранится на GitHub

Исходники, Dockerfile, Compose и инструкции. Образы и модели собираются/скачиваются на компьютере и переносятся через флешку. Приватная база и таблица паролей публиковаться не должны; имена файлов и папок добавлены в `.gitignore`.

Если вы изменили исходники после этого выпуска, перед экспортом выполните `py tools/source_manifest.py`, затем `py tools/ib.py start --build`. Это обновляет список переносимых исходников и пересобирает соответствующие образы. Генератор манифеста исключает базы, ключи, материалы, кэши и известные файлы аккаунтов; не кладите приватные данные в файлы исходников.
