# ИБ — M3 + M4

Обновление для работающего M2.5. Все файлы в архиве полные. Размещение в интернете не выполняется.

## Что сделано

M3: публикация задач C++20 из редактора курса, стартовый код, условие, ограничения, скрытые тесты, пробный запуск со своим вводом, проверка решения, очередь, отмена, сообщения об ошибках, история отправок и восстановление их кода в редактор. Принятое решение завершает блок и даёт один балл, включая анализ времени и комментариев M2.5.

M4: автосохранение кода и своего ввода на сервере, защита от перезаписи другой вкладкой, скачивание кода, продолжение незавершённого блока из библиотеки/профиля, фильтры библиотеки, переход к следующему блоку и навигация по курсу, восстановление позиции загруженного видео.

## Важно перед установкой

- На этом компьютере должен уже работать M2.5. Не устанавливайте архив прямо поверх M1.
- Исправленную ранее миграцию `courses/0002_course_is_listed_material_required_and_more.py` НЕ ЗАМЕНЯЕМ. В архиве нет старых миграций courses, accounts, access, studio и learning. Новая миграция только в приложении practice.
- База, ваши настройки, файлы студентов, курсы, пароли и локальное отключение 2FA не входят в архив и не заменяются.
- Не запускайте `makemigrations --merge`, `--fake`, `import_existing.py` и повторную инициализацию проекта.
- Компиляция требует Docker Desktop с Linux-контейнерами. Сайт и теория могут работать без Docker, отправка программ тогда показывает, что обработчик выключен.

## 2. Один раз установить Docker Desktop

Если Docker Desktop уже установлен и запускает Linux-контейнеры, пропустите установку.

Официальная инструкция и установщик Windows: https://docs.docker.com/desktop/setup/install/windows-install/

Для отсутствующего WSL откройте Windows Terminal / PowerShell от имени администратора:

```powershell
wsl --install --no-distribution
```

Перезагрузите Windows, если система попросит. Затем:

```powershell
wsl --update
```

Установите Docker Desktop, выбрав WSL 2. Запустите приложение и дождитесь готовности Engine. В настройках используйте WSL 2 based engine. Нужен режим Linux containers, не Windows containers. Если Docker сообщает, что виртуализация отключена, сначала включите её в UEFI/BIOS по инструкции производителя компьютера.

Вернитесь в терминал VS Code (после установки его может потребоваться открыть заново):

```powershell
docker version
```

Должны отображаться Client и Server без ошибки соединения. Проверка режима:

```powershell
docker info --format '{{.OSType}}'
```

Ожидается `linux`.

В корне проекта соберите образ:

```powershell
docker build -t ib-cpp-runner:m34 .\runner
```

Первый запуск скачивает базовый образ и компилятор, поэтому потребуется интернет и несколько минут. Это загрузка инструментов, а не публикация платформы. После сборки проверки запускаются без доступа контейнеров к интернету.

Ожидается `Все проверки Docker пройдены.` Если проверка падает, не используйте компилятор для студентов: пришлите вывод, чтобы исправить реальную причину. Не отключайте ограничения ради запуска.

## 4. Создать первую задачу

Лучше создайте НОВЫЙ тестовый курс. По правилам версий M2 старые учащиеся остаются в своей опубликованной версии, а новые задачи старой версии задним числом не добавляются.

В редакторе: добавьте урок → блок C++ → заполните поля.

Название: `Сумма двух чисел`.

Условие: `Прочитайте два целых числа и выведите их сумму.`

Ввод: `Два целых числа a и b, каждое от -1000000 до 1000000.`

Вывод: `Одно число — сумма a и b.`

Пример: `Ввод: 2 3. Вывод: 5.`

Стартовый код:

```cpp
#include <iostream>

int main() {
    return 0;
}
```

Скрытые тесты (кнопка «Скрытый тест» в закрытой проверке):

| Ввод | Ожидаемый вывод |
| --- | --- |
| 2 3 | 5 |
| -8 3 | -5 |
| 0 0 | 0 |
| 1000000 1000000 | 2000000 |

Лимиты: 2 секунды, 128 МБ. Сохраните и опубликуйте курс. Эталонное решение можно хранить в редакторе; оно не передаётся студенту и само по себе не заменяет тесты. В этом выпуске оно не проверяется автоматически перед публикацией.

Студентом в приватном окне добавьте курс в библиотеку и откройте блок. Решение:

```cpp
#include <iostream>

int main() {
    long long a, b;
    std::cin >> a >> b;
    std::cout << a + b;
}
```

В поле своего ввода напишите `2 3`, нажмите «Запустить на своём вводе». В истории откройте «Вывод и сообщения»: должно быть `5`. Пробный запуск не даёт баллы.

Нажмите «Отправить на проверку». После проверки должно появиться «Решение принято», 4/4 теста, блок пройден и начислен 1 балл. Повторная успешная отправка второго балла не даёт. В закрытой аналитике будет применено правило M2.5 по времени и комментариям.

## 5. Проверить M4

1. Измените код, подождите надпись «Сохранено», обновите страницу: код и свой ввод должны восстановиться.
2. Откройте этот же блок в другой вкладке и сохраните разные изменения. Устаревшая вкладка получит сообщение о конфликте, а не перезапишет новую версию. Скачайте нужный код кнопкой «Скачать .cpp», затем обновите вкладку.
3. Перейдите в библиотеку → «Продолжить»: откроется последний незавершённый посещённый блок, либо первый ещё не пройденный.
4. Добавьте в новый курс загруженное видео. Посмотрите часть, поставьте на паузу, дождитесь сохранения позиции. После повторного открытия воспроизведение продолжится с неё.
5. Видео по внешней ссылке открывается у другого сервиса; его позицию наша платформа не сохраняет.
6. Кнопка «Следующий блок» открывает следующий блок по программе; оглавление показывает зелёные отметки завершения.
7. Отправьте решение, нажмите «Отменить» в истории. Отменённая отправка не даёт баллы. Уже завершённый результат отмена не отнимает.

Редактор — локальный текстовый редактор с моноширинным шрифтом, Tab, Ctrl+S, автосохранением и скачиванием. Подсветка синтаксиса/автодополнение IDE в этот выпуск не входят. Видеопозиция сохраняется каждые 5 секунд и при паузе/перемотке; при аварийном закрытии возможна потеря последних секунд. Завершение видео не начисляет балл автоматически: остаётся явная отметка ознакомления.

## 6. Ограничения проверки

- C++20, программа читает stdin и пишет stdout. Это пакетная проверка, не интерактивный терминал.
- Вывод сравнивается по последовательности слов/чисел; разделяющие пробелы и переводы строк несущественны. Нет специального сравнения чисел с плавающей точкой, частичных баллов и пользовательских проверяющих программ.
- Ввод для запуска до 10 КБ, код до 100 КБ, вывод до 64 КБ. Скрытых тестов до 100. Каждый тест выполняется в новом контейнере; это может быть заметно медленнее запуска большого сервиса.
- Одновременно допускается одна активная отправка на пользователя; до 10 запусков в минуту. Один worker проверяет задания последовательно. Для домашней разработки запускайте один worker.
- При отказе Docker выдаётся ошибка проверки. Платформа не переключается на выполнение кода в Windows.
- История хранит отдельные неизменяемые отправки. Пробные запуски не входят в число попыток зачёта. Ошибки компиляции и неверные решения при проверке учитываются; инфраструктурные ошибки не ухудшают аналитику.
- Время для M2.5 заканчивается при получении успешной отправки сервером, не после ожидания в очереди.
- Если worker принудительно завершён, его задача после истечения срока обработки перейдёт в ошибку при следующем запуске worker; её можно отменить и отправить заново. Штатная остановка Ctrl+C помечает текущую задачу как ошибку.
- Старые опубликованные заглушки C++ без Task остаются недоступными: преподаватель создаёт настроенную задачу в новой публикации. Исторические баллы/таймеры не переписываются.

## 7. Изоляция

Веб-процесс только записывает отправку. Отдельный доверенный worker вызывает Docker без shell-команд из кода студента. Контейнеры работают без сети, без прав root, без дополнительных Linux capabilities, с запретом повышения привилегий, ограничениями CPU, памяти, процессов, времени и вывода. Корень файловой системы только для чтения, временная рабочая папка уничтожается вместе с контейнером. Файлы проекта, база, секреты и Docker socket внутрь не монтируются.

Ожидаемые ответы остаются в памяти worker; контейнер получает только ввод текущего теста. Сравнение выполняет worker. Сведения браузера «passed=true» не используются. Docker разделяет ядро Linux со средой выполнения: это не обещание абсолютной защиты от ошибок ядра. Перед интернет-размещением кафедре нужно проверить и настроить отдельную среду выполнения; сейчас это локальный прототип без публикации.
